# dev-footer behavior

Draws everything below the editor and the transcript rows of dev's background work: the subagent list, the HUD, and the renderers for `work` calls and `dev/work-outcome` messages. Presentation only. Dev supplies facts and depends on no extension; this extension adapts to dev's contract ([ADR 0006](https://github.com/taekwondodev/dev/blob/main/docs/adr/0006-global-visual-layer.md), live view and model-visible results in dev's `docs/work.md`). The HUD works in plain `pi`; the list and the work rows render nothing without dev. Glyphs assume Ghostty with JetBrainsMono Nerd Font Mono, without fallback. Ghostty's targeted `font-codepoint-map` draws icons from JetBrainsMono Nerd Font; each icon occupies one column followed by two spaces. No glyph stretches over the whole cell height: gauges use centered horizontal lines and no row uses `│` or block elements.

Spacing: the editor stays the only element drawn with lines. Pi adds one spacer above the below-editor container only when it is non-empty; the list adds no blank row below itself and the HUD always begins with one blank row. With children: editor, blank, list, blank, HUD. Without: editor, blank, HUD.

Untrusted text: everything a child, a command or a session file supplies is cleaned where it enters, before drawing. Control characters become spaces, so no OSC, CSI or C1 sequence reaches the terminal; transcript rows keep newlines and tabs, list fields lose them so each child stays one row. Text decoded after entry, such as a result contract's JSON fields, is cleaned again. The HUD cleans folder, branch, session, model and link text the same way, on one row, and links an `origin` only when its owner and repository are plain GitHub names (letters, digits, `.`, `_`, `-`).

## Subagent list

A below-editor widget, set again on every `session_start`. It keeps the latest `dev/work-view` of the current session and ignores views of other sessions and payloads without the view's shape. Dev owns the batch: the view holds active children and children that finished after the owner's last message, so finished rows stay until the owner writes again. An empty view renders no rows.

- **Rows.** One aligned row per child: status glyph (spinner in `accent` while running, `◌` waiting, `✓` completed in `success`, `✗` failed in `error`, `⊘` cancelled), title (invoked skill, else `coordinator`, `reader` or `writer`) in bold, `accent` while running or waiting and `muted` once settled, task key with hyphens as spaces, then the current activity: the running tool's name in `toolTitle` and its target in `muted`, `thinking…` and `writing…` in italic `thinkingText`, `retrying: <message>`, the error in `error` for a failed child, nothing for a settled one. Title, task and activity align in columns.
- **Right column.** Model · `↻ turns` · context percentage · duration, in `muted` with `dim` separators. The percentage turns `warning` from 60% and `error` from 85% only while the child runs. Below 100 columns model and context drop; the task is cut before the activity, which keeps a reserve of 14 cells.
- **Order and overflow.** Children are ordered running, waiting, failed, cancelled, unknown, completed; running local commands are one `muted` line (`1 command running`) placed right after the live rows (running or waiting, with their leaves) and before the settled rows and the overflow; running rows keep start order, settled rows show the latest first so the overflow hides the oldest. Leaves follow their coordinator, indented with `└`; a group with a running leaf ranks as running. At most 5 child rows, then `+N` with counts per status.
- **Blocking notices.** Last; each blocking notice is its own `warning` row: subscription exhausted with agents blocked, lead failed with automatic reactivation suspended.
- **Motion.** While a child is running or waiting the list redraws every 100 ms for the spinner and durations; otherwise it schedules nothing.

## HUD

Replaces Pi's footer in interactive sessions; `/footer` toggles back to Pi's default footer and again. A blank row, then a two-by-two grid with no status row and no separator rule and no background. Icons carry one calm hue, `syntaxType` (pine in rose-pine-moon), and values carry luminance: primary values in `text`, secondary ones in `muted`. Any other color marks state, with one exception: the branch icon is drawn in `accent` as the anchor of where you are.

- **Row 1.** Left, where you are: folder name in bold, branch name in `text` after its `accent` icon, pull request `#N` in its state color (open `warning`, draft `muted`, merged `syntaxKeyword`, closed `error`), diff `+added` in `toolDiffAdded` and `−removed` in `toolDiffRemoved` (hidden when clean). Folder, branch and pull request are OSC 8 links to GitHub when `origin` is on GitHub and the terminal supports hyperlinks. Right: model, then the thinking level in the color Pi uses for the editor border.
- **Row 2.** Left: session name in italic `muted` and the number of live linked worktrees in `muted` (hidden at 0). Right, right-aligned to the same column: context gauge, filled in `syntaxType` at rest, and percentage in `text` (both `warning` from 60%, `error` from 85%), cost in `text` when above zero, latest cache hit rate with one decimal in `muted`, cache clock, sparkline of tokens per run (last 8 runs) in `muted` with the latest run in `success`.
- **Cache clock.** Counts down `m:ss` from 5:00 after the latest request, real or cache-warming, then shows a static `stale` and stops ticking. The icon is `success` while the cache is warm, `warning` in its last minute and `dim` once stale; it is followed by two spaces.
- **Narrow terminals.** Below 100 columns the grid drops the session name, worktree count, pull request, cache hit rate and sparkline and shortens the gauge from 10 to 6 cells; folder, branch, diff, model, context and clock stay. Narrower still it drops cost, then diff, then the gauge, then the thinking level. No row exceeds the width; text is cut only when even the narrowest layout does not fit.
- **Repository facts.** Read only in the background, never from `render()`: `git --no-optional-locks diff HEAD --shortstat` and `git ls-files --others --exclude-standard` at session start, branch change and the end of each turn, one read at a time; and `gh pr view <branch>` only for a GitHub `origin`, never on the default branch or a detached head, at most once a minute per branch. The diff counts staged and unstaged changes against `HEAD` plus the lines of untracked, unignored text files (at most 500, each up to 1 MiB; binary files count zero); without a commit there is no diff. Nothing runs while idle.
- **Statistics.** Rebuilt only when the session, leaf or model changes; cost covers every entry, the rest follows the active branch.

## Transcript rows

Renderers for the existing `work` calls and `dev/work-outcome` messages, drawn from call arguments and `details`, never from model-visible content. They cost no tokens. dev-hush still hides them when active.

No decorative symbols: a block's only glyph is its status (`✓` in `success`, `✗` in `error`, `⊘` cancelled), plus `└` before the summary.

- **Delegation.** A static one-line launch row: `<title>  <task>` (title in bold `accent`, task in `text`), completed when the result arrives with `<model> · <level> · <access>` dimmed, where the thinking level appears only when the dispatch requested one, in the color Pi uses for the editor border.
- **Child outcome.** One block per child: `<glyph> <title>  <task>`, then indented under the title `<model> · <level> · <N> turns · <N> calls · <tokens> tokens · <duration>` in `muted` with the level in its thinking color, the call count hidden at zero and the duration without a leading zero unit (`2s`, `1m 05s`), then `└` under the glyph with the result summary and the ctrl+o key dimmed at the right edge of the block. The summary is, for an answer opening with a fenced JSON object carrying `format` and `status`, `format · status · <count> <list>` for each top-level array, otherwise its first non-empty line; a failed child shows its error. On ctrl+o: "Child work", the child's tool calls turn by turn, numbered, (codemode calls by their nested calls, targets from the same allowlist and redaction as dev's live activity, so no command or script text, secret-like values or opaque URL path segments, at most 120 characters each), then "Answer" and the answer, cut after 22 lines.
- **Session file.** The trail, and the answer when the outcome carried only a pointer, come from the child session file named in the outcome `details`. It is read once, asynchronously, at most 8 MiB; a missing or oversized file is reported in place of the trail. A finished read asks for one redraw.
- **Other actions.** One call line and one dimmed result line each: `work inspect`, `work list`, `work dispatch`, `work cancel`, and `$ <command>  <task>` alone for a process launch; ctrl+o shows the page text, the records or the rules. A command outcome is one row: `✓ $ <command>  exit N · <duration>`, `✗` for a nonzero exit; ctrl+o shows its output tail. Errors show their first line in `error`.

## Performance

`render()` does no I/O: the list draws the latest view, the HUD the last background read, the renderers `details` and cached session reads. One list and HUD frame stays far below a 16 ms frame.

Verify with `node check.mjs`. Its fixtures are real payloads: views built by dev's own view builder from the replay of two real children, and a lead's work results, outcome messages and child session files from a run of dev with scripted children.
